# An original craft example: The Very Busy Marble Works

This invented toy system demonstrates an explanatory story. It is not a claim about a real factory, a user-approved sample, a recorded narration, or a rendered animation. Timing below is estimated. It deliberately uses an explicit model so the mechanism can be checked without borrowing an unverified scientific claim.

## Model and evidence

Our fictional machine works in one-minute steps. Six marbles enter a waiting tray each step; a polisher removes three and finishes all three within that step. There is enough tray space, and no marbles are lost or diverted. These are invented model assumptions, not measured facts.

| ID | Claim | Basis and limit |
|---|---|---|
| C01 | After each step the waiting tray contains three more marbles. | Defined model: change in waiting count = 6 arrivals − 3 completions = 3 per step. Starting at zero, the end-of-step counts are 3, 6, 9. No claim about within-step timing. |
| C02 | A faster incoming belt alone does not raise this polisher's completion rate. | The model fixes the polisher at three completions per step. Real machinery can have additional constraints and interactions excluded here. |

## Spoken passage

> Welcome to the Very Busy Marble Works. Six marbles arrive every minute. The polisher can finish three.
>
> Business is booming. Mostly in the waiting tray.
>
> After one minute, three marbles are still waiting. After two, six. The tray is quietly becoming the busiest department in the company.
>
> So we install a faster delivery belt. Surely that will help?
>
> Look at the polisher. Same machine. Same three marbles a minute. We have made the queue grow faster. We have not made the work finish faster.
>
> To improve this little factory, we first need to find the part that limits its output.

## Why these choices help

- **Hook:** A small mismatch gives the viewer something concrete to solve. No disaster or cosmic claim is needed.
- **Mechanism:** The queue grows because arrivals exceed completions. Counting comes before terminology.
- **Humor:** The waiting tray becomes a “department”; this changes the tone, not the arithmetic.
- **Transition:** The failed intervention creates a reason to examine the limiting machine. The next section is earned by the preceding demonstration.
- **Analogy boundary:** The factory can later illustrate a bottleneck, but it does not establish that every real system has a single fixed limiting component. Name that limit if transferring the model to a real case.
- **Visual progression:** One persistent layout changes state with the explanation. It needs purposeful animation, not four unrelated decorative keyframes.
